201 Created - это специальный HTTP-статус для успешного создания ресурса.
Content-Type: application/json - это HTTP-заголовок, который сообщает серверу о том, что мы отправляем данные в json формате

![alt text](screenshots/04-update.png)
POST создаёт новый ресурс, а PUT обновляет или заменяет существующий по его идентификатору.
При создании комментарий добавляется в коллекцию поста, поэтому нужен post_id, а при обновлении достаточно уникального comment_id, так как он уже существует в базе.


![alt text](screenshots/05-delete.png)
POST: 201 Created, потому что запрос успешно создал новый ресурс на сервере.
PUT: 200 OK, так как сервер корректно обновил существующую запись по её идентификатору.
DELETE: 204 No Content, поскольку ресурс удалён и тело ответа намеренно оставлено пустым.
GET: 200 OK, потому что сервер успешно извлёк и передал клиенту запрашиваемые данные.

Функция esc() экранирует пользовательский ввод, превращая опасные символы вроде < и > в безопасные HTML-сущности, чтобы предотвратить выполнение вредоносного кода.
Если её не вызвать, человек может вставить <script> в комментарий, и этот код выполнится в браузере каждого посетителя страницы (уязвимость XSS).

Сервер отправляет только пустой HTML-шаблон («скелет») со скриптами, а сам контент загружается браузером через JavaScript (React) уже после открытия страницы, поэтому «View Source» показывает состояние страницы до выполнения скриптов. Большинство протых ботов увидят пустую страницу и проигнорируют сайт.

![alt text](screenshots/15-xss.png)
Vanilla JS:
Надо явно использовать textContent вместо innerHTML или создавать функции экранирования (как esc()), которые превращают < и > в безопасные HTML-сущности перед вставкой в DOM.
React:
Защита автоматическая - React экранирует все значения в JSX-выражениях {variable} по умолчанию, превращая опасные символы в безопасный текст без участия разработчика.
React надёжнее, так как защита встроена по умолчанию и не зависит от внимательности разработчика
